pidx

PDF → 树索引 → LLM 推理检索（无向量、无切块）
演示Pipeline接口文档
约定 快速上手 文档 上传 列表 详情 / 状态 重建索引 删除 资料包（zip） 内容 树 页文本 版面块 页图 / 原文件 检索 流式检索 错误 MCP / CLI 配置

约定

REST + JSON。接口形状和 PageIndex SDK 的 submit_document / get_tree / get_page_content / get_block 对应，另外加了 /v1/search。

项说明
Base URL就是当前页面所在的地址（去掉 /api-docs）。本机默认 http://127.0.0.1:8890。
经反代挂到公网时（见 README「部署」），需要 token：浏览器用 ?token=… 打开一次即可（之后靠 cookie），程序调用用 Authorization: Bearer <token>。本机 / 内网直连不需要 token。
doc_idpi- 加 12 位十六进制，例如 pi-48b6064602a4。
状态queued → processing → completed / failed。重建索引期间仍然用旧树提供 tree 和 search，新树建好后整体替换。
页码从 1 开始的物理页码（第几页 PDF 页面），不是印在页面上的页码。
节点node_id 是 4 位字符串，按先序遍历编号（"0000" 起）；start_index / end_index 是节点覆盖的页码范围（含子节点）。
版面块block_id 形如 p42_b2（第 42 页第 2 块）。bbox = [x0, y0, x1, y1]，单位是页面宽 / 高的千分之一，原点在左上角，和 PageIndex 一致。
耗时建索引是异步的，大约每页 0.3–1 秒，扫描件要慢得多。检索用 DeepSeek 时通常 2–8 秒，用 Atria 时 15–75 秒，客户端超时建议设到 ≥300 秒。

快速上手

BASE=http://127.0.0.1:8890   # 或你的部署地址

# 1. 上传
curl -F file=@report.pdf $BASE/v1/documents
# → {"doc_id":"pi-48b6064602a4","name":"report.pdf","status":"queued"}

# 2. 轮询，直到 status = completed
curl $BASE/v1/documents/pi-48b6064602a4

# 3. 提问
curl -X POST $BASE/v1/search -H 'Content-Type: application/json' -d '{
  "query": "How many formal enforcement actions did the Federal Reserve complete in 2023?",
  "doc_ids": ["pi-48b6064602a4"], "answer": true, "include_text": false }'

文档

POST

/v1/documents

上传一个文件，立刻返回 doc_id，索引在后台建立。请求格式是 multipart/form-data。支持 PDF、图片（png / jpg / jpeg / jp2 / webp / gif / bmp）、Word / PPT / Excel（doc / docx / ppt / pptx / xls / xlsx）；zip 请用 POST /v1/collections。

字段类型默认说明
filefile必填按扩展名判断格式，并检查文件头。图片和 Office 文件需要配置 MinerU。
modestringauto只对 PDF 有效。auto：每页少于 80 字符时自动走 OCR；text：只用文本层；ocr：强制走 MinerU。图片总是走 OCR。
summarybooltrue是否生成节点摘要。关掉能省掉大部分 LLM 调用，但树检索的准确度会下降。
metadataJSON string{}自定义元数据，原样保存并返回。
{"doc_id": "pi-48b6064602a4", "name": "2023-annual-report.pdf", "format": "pdf", "status": "queued"}

如果重名，会自动改名为 name_1.pdf、name_2.pdf……

format解析页引用
pdfPyMuPDF；扫描件走 MinerU物理页bbox，可在页图上高亮
image包成单页 PDF 后走 MinerU OCR1 页bbox，可在原图上高亮
officeMinerU 原生解析虚拟页：PPT 每张幻灯片、Excel 每个工作表各一页，长内容按约 1500 token 再切；页带 labelbbox: null，只有文本；没有页图
GET

/v1/documents

参数：limit（1–10000，默认 50）、offset、collection_id（只列某个资料包里的文件）。按创建时间倒序。

{"documents": [ {…同下方详情…} ], "total": 4, "limit": 50, "offset": 0}
GET

/v1/documents/{doc_id}

文档信息和状态。info 里是建索引的诊断信息。

{
  "id": "pi-8c61a88a0be0",
  "name": "q1-fy25-earnings.pdf",
  "status": "completed",
  "error": null,                       // failed 时是错误信息
  "pageNum": 22,
  "description": "This document is a quarterly earnings press release issued by The Walt Disney Company …",
  "metadata": {},
  "createdAt": 1793170384.02,
  "format": "pdf",                     // pdf | image | office
  "pageImages": true,                  // 有没有页图（office 为 false）
  "collectionId": null,                // 来自 zip 时是资料包 id
  "relPath": null,                     // 来自 zip 时是包内路径，如 "02_财务/2025年度预算.xlsx"
  "info": {
    "parser": "pymupdf",               // pymupdf | mineru | mineru-office
    "method": "layout+llm",            // bookmarks | layout+llm | llm-pages | page-groups

    "body_size": 12.0,                 // 正文字号

POST

/v1/documents/{doc_id}/reindex

重新建索引。可选 query 参数 mode、summary，传了就覆盖上传时的设置。重建期间旧树继续可用。

{"doc_id": "pi-48b6064602a4", "status": "queued"}
DELETE

/v1/documents/{doc_id}

删除文档，同时删除它的页、块、树和原文件。

{"message": "Document deleted successfully."}

资料包（zip）

POST

/v1/collections

上传一个 zip（multipart：file，可选 summary）。目录结构成为资料包的目录树，每个支持格式的文件成为一个文档，分别在后台建索引；全部完成后再给每个目录写摘要。只有一个顶层目录时把它当作根。GBK 文件名会自动识别；__MACOSX、隐藏文件直接忽略，不支持或损坏的文件列在 skipped 里。

{"collection_id": "pc-cf88552ba20d", "doc_ids": ["pi-…", …], "files": 10,
 "skipped": [{"path": "README.txt", "reason": "unsupported format"}], "status": "processing"}

上限（可用环境变量调整）：1000 个文件，单文件 200 MB，解压后合计 2 GB。

GET

/v1/collections

资料包列表：id、name、status（processing → completed / failed）、info（文件数、目录数、skipped）、counts（各状态的文件数）。

GET

/v1/collections/{collection_id}

同上，外加目录树 tree：

{"type": "dir", "title": "星河储能项目资料", "path": "", "node_id": "d0000", "summary": "…", "nodes": [
  {"type": "dir", "title": "02_财务", "path": "02_财务", "node_id": "d0002", "summary": "…", "nodes": [
    {"type": "file", "title": "2025年度预算.xlsx", "path": "02_财务/2025年度预算.xlsx", "doc_id": "pi-…",
     "status": "completed", "pageNum": 3, "format": "office", "description": "…"}]}]}
DELETE

/v1/collections/{collection_id}

删除资料包和它的所有文档。

GET

/v1/documents/{doc_id}/pages?pages=5-7,9

页文本，已去掉页眉页脚。pages 支持区间和逗号分隔，例如 "12"、"5-7"、"3,8"。

{"doc_id": "pi-48b6064602a4",
 "pages": [{"page_index": 42, "markdown": "written agreements, prompt corrective action directives, …"}]}
GET

/v1/documents/{doc_id}/blocks/{block_id}

单个版面块。block_type 可能是 text、image、title、table……（后三种来自 MinerU）。

{"doc_id": "pi-48b6064602a4", "page": 42, "block_id": "p42_b2",
 "bbox": [147, 175, 821, 187], "block_type": "text",
 "text": "In 2023, the Federal Reserve completed 63 formal enforcement actions. Civil money penalties"}
GET

/v1/documents/{doc_id}/pages/{page}/image

页面渲染成 PNG。参数：highlight（逗号分隔的 block_id，在图上高亮）、zoom（默认 1.5）。可以直接放进 <img> 展示引用。

<img src="$BASE/v1/documents/pi-48b6064602a4/pages/42/image?highlight=p42_b2,p42_b3">
GET

/v1/documents/{doc_id}/file

原文件（PDF、图片或 Office 文件）。PDF 拼上 #page=N 可以在浏览器里直接跳到第 N 页。

检索

POST

/v1/search

在树上做推理检索，可以顺带生成带块级引用的答案。过程见 Pipeline。

字段类型默认说明
querystring必填问题，中英文都可以。
doc_idsstring[]null只在这些文档里搜。不传就搜全库（或 collection_id 指定的资料包）：按向量给文档排序取前 30，再由 LLM 读文档描述（资料包的文件按目录树给出）挑出最多 5 篇。
collection_idstringnull只在这个 zip 资料包里搜。
retrievalstringhybridhybrid：节点向量召回最相关的几棵子树，LLM 并行阅读；tree：LLM 读整棵树（大树分层展开）。没有向量时自动用 tree，实际用的方式见响应里的 retrieval。
top_kint5每篇文档、每轮最多选几个节点。
answerboolfalsefalse 时只返回命中的节点（适合把结果交给你自己的 LLM）；true 时额外生成答案和引用。
max_roundsint2只在 answer=true 时生效：证据不足时最多再检索几轮。
include_textbooltrue返回的节点是否带完整原文。
llmstringdeepseek检索用哪个模型：deepseek（V4 Flash，快）或 default（建索引用的模型，默认是免费的 Atria，慢约 10 倍）。可选值见 GET /v1/llm。

POST

/v1/search/stream

请求体和 /v1/search 相同，返回 Server-Sent Events，每条是 data: {json}。演示页的过程时间线就是用这个接口做的。

type何时 / 内容
start开始：library（可检索的文档）、llm、retrieval
embed问题向量算完：ok、ms
docs选完文档：selected、thinking、shortlist（向量排序前 10 及分数）；单文档时 skipped=true
tree_search_start / tree_search每轮、每篇文档的树检索：thinking、nodes、how。how.mode 是 hybrid（anchors_total，以及召回的每棵子树的 label、向量分数、LLM 相关度、选中的节点）、full（整棵树一次读完）或 layered（分层展开）
llm每次 LLM 调用结束时的打点（字段同 timing.calls）
read送入作答的节点数、版面块数、token 数
answer_start / answer_delta / answer_done答案逐段输出（text）；结束时给出 answer、citations、sufficient
insufficient证据不足，即将补搜：missing
done最终结果 result，内容同 /v1/search 的响应
curl -N -X POST $BASE/v1/search/stream -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"query":"…","answer":true}'
GET

/v1/llm

列出可用的检索模型和默认值。

{"default": "deepseek", "backends": [{"name": "default", "label": "Atria-Dawn-Preview（建索引用的模型）", "model": "Atria-Dawn-Preview"},
                                    {"name": "deepseek", "label": "DeepSeek V4 Flash", "model": "deepseek-v4-flash"}]}
答案里的引用标签是 [文档序号:block_id]，文档序号对应 documents 数组的下标加 1。前端可以把标签替换成可点击的链接，指向 /pages/{page}/image?highlight={block_id}。

库里没有可搜的文档时返回 {"query", "error": "no completed documents to search", "nodes": []}。

错误

HTTP情况
400不支持的格式、文件头和扩展名不符或无法打开；zip 里没有可用文件或超过上限；block_id 格式不对
404doc_id、collection_id、block 不存在，页码超出范围，或 Office 文档请求页图
422参数校验失败（FastAPI 默认格式，detail 里有具体字段）
500LLM 连续重试后仍失败等内部错误。建索引失败不会返回 500，而是把文档状态置为 failed 并写入 error

调用 LLM 时遇到 429/502/503/504 会自动退避重试（优先遵守 Retry-After），最多 6 次。

MCP / CLI

MCP（stdio）：内部调用上面的 HTTP 接口，提供 list_documents、list_collections、get_collection、get_tree、get_pages、search 六个工具。

claude mcp add pidx -e PIDX_API=http://127.0.0.1:8890 -- \
  /path/to/pidx/.venv/bin/python -m pidx.mcp_server

CLI：

python -m pidx serve [--port 8890]               # 或 scripts/serve.sh start|stop|restart
python -m pidx index report.pdf [--mode ocr]     # 上传并等待索引完成；也可以是图片、Office 文件
python -m pidx index 资料.zip                     # zip → 资料包
python -m pidx tree pi-48b6064602a4
python -m pidx ask "问题" [--doc pi-xxx ...] [--collection pc-xxx] [--retrieval hybrid|tree] [--no-answer]

自动生成的 OpenAPI 文档在 /docs（Swagger UI）。

配置（环境变量 / .env）

变量默认说明
PIDX_LLM_BASE_URL / _API_KEY / _MODELAtria 网关建索引用的模型（backend default），任意 OpenAI 兼容端点。没设时回退到 ATRIA_* 变量。
DEEPSEEK_API_KEY / PIDX_DEEPSEEK_MODEL— / deepseek-v4-flash设置了 key 才会启用 backend deepseek。
PIDX_SEARCH_BACKEND配置了 DeepSeek key 时为 deepseek，否则为 default检索默认用哪个模型。
PIDX_PUBLIC_TOKEN—经公网反代进来的请求（带 X-Forwarded-For）必须带这个 token。
PIDX_LLM_CONCURRENCY24进程内 LLM 并发上限（Atria 每个项目上限 100）。
SILICON_FLOW_API_KEY / PIDX_EMBED_MODEL— / BAAI/bge-m3向量（SiliconFlow）：建索引时给每个节点和文档描述算向量；检索时给文档排序、召回子树。没有 key 时检索退回纯 LLM 读树。
PIDX_RETRIEVALhybrid默认召回方式：hybrid 或 tree（请求里的 retrieval 优先）。
PIDX_ANCHOR_TOKENS / PIDX_ANCHORS_PER_DOC3000 / 3hybrid：每棵子树骨架的大小上限；每篇文档并行读几棵子树。
PIDX_DOC_SHORTLIST30选文档时交给 LLM 的候选文档数（按向量排序）。
PIDX_VIRTUAL_PAGE_TOKENS1500Office 文件的虚拟页大小。
PIDX_ZIP_MAX_FILES / _FILE_MB / _TOTAL_MB1000 / 200 / 2048zip 资料包的上限。
MINERU_API_KEY / PIDX_MINERU_MODEL— / pipeline扫描件、图片 OCR 和 Office 文件解析（mineru.net 云端 API，PDF 单文件最多 200 页，超出的会自动切段）。PIDX_MINERU_MODEL 可选 pipeline 或 vlm。
PIDX_MINERU_URL—设置后改用自建的 MinerU 服务（例如 spark-0:8880），不再调用云端。
PIDX_MAX_PAGES_PER_NODE / _TOKENS_10 / 20000超过阈值的叶子节点会被继续拆分。
PIDX_MAX_SPLIT_DEPTH3递归拆分的最大深度。
PIDX_INDEX_WORKERS2同时建索引的文档数。
PIDX_DATA_DIR./dataSQLite 数据库和原 PDF 的存放位置。
